## 1. “独立”的当前范围

按接口文档第一阶段方案，新项目独立部署 Boot 进程，复用所需业务表和原认证 Redis。验证码、普通登录、退出、用户信息仍由原服务提供；用户、角色、菜单维护也留在原服务。不能因此直接停掉整个旧应用。

完全独立数据库、独立认证属于额外设计，不是本次已有框架自动具备的能力。

契约来源：[智能门锁与智能班牌新项目接口文档](D:/CodingFiles/School/assessment-back-v2/assessment/doc/智能门锁与智能班牌新项目接口文档-JDK21-SpringBoot3.5.7.md)。

## 3. 迁移前先补齐的基础兼容点

| 优先级 | 当前问题 | 必须处理 |
| --- | --- | --- |
| P0 | 身份接口没有生产实现，有效 JWT 进入认证流程仍可能返回 503 | 实现唯一 IdentityResolver Bean，读取真实用户、禁用状态、当前角色权限；学院范围从服务端身份读取 |
| P0 | Authentication 的 principal 是普通 Identity record | 实现 Principal / AuthenticatedPrincipal 的 getName() 或调整 principal 构造，确保 authentication.getName() 返回用户名 |
| P0 | SDK 自有连接分配器尚未纳入生命周期 | 对真实 ConnectorAllocator、监听器和 SDK 线程组进行初始化/释放管理；统一设备启用开关 |
| P1 | ApiResult 仅有 error(int,String) | 补齐旧默认 code/msg、ok/error 重载及 fluent put，保持文档中不同响应结构 |
| P1 | 作息配置与旧服务调用不兼容 | 适配 Map<Integer,LocalTime>；恢复等价 policyKey 规则指纹，更新旧 import 与调用 |

身份名称问题已用当前 Identity 构造实际 Authentication 复现：getName() 返回 Identity[userId=…, username=…, …]，而非用户名。旧 CourseScheduleController、SwitchRecordController 按 getName() 查用户，直接迁移会查不到用户；审计操作者也可能写错。需要增加名称回归验证。

- [JwtAuthenticationFilter](../assessment-server/src/main/java/com/hnkjzyxy/ab/security/JwtAuthenticationFilter.java)

旧 CoursePeriodResolver 将 starts/ends 取值当作 String，新类改为 LocalTime，不能直接复制编译。旧 ScheduleWriteCoordinator 依赖 policyKey() 判断覆盖数据可信度，新类当前没有此方法；不能只用固定版本字符串替代规则内容指纹。

当前 NettyConfig 管理的是新建线程组，尚未接入 SDK 的 ConnectorAllocator.GetAllocator()。因此现有线程释放测试不能证明厂商 SDK 连接和线程已正确释放。迁移旧 CommandAllocator 时还要移除默认设备地址/凭据，核实 RestartCount=2 对写命令的重试行为；结果未知的动作不得自动重新提交。

## 4. 业务迁移仍未实施

接口文档包含 8 个控制器、60 条业务路由，其中 2 条废弃写入口固定拒绝；另有 4 条外部认证接口。新工程尚无这些生产 Controller、Mapper 或业务 Service。

需要迁移：
1. 教室、班牌绑定读取与相关身份读取。
2. OA / 本地课表、调课、停课、来源复核、课表事务发布。
3. 考试生命周期、冲突、行版本、审计历史。
4. 教室占用快照、完整排程、问题收敛与可信覆盖。
5. 门锁发现、绑定、动作、状态读取、任务、回执及人工复核。
6. 开关记录、门禁密码兼容入口。

同时迁移必要 Entity/DTO/VO、Mapper XML、数据库锁、事务协调器、字段填充、时间解析与业务异常。保持请求方法、路径、字段、时间格式、返回变体和学院权限；升级 javax 到 jakarta，并适配目标 MyBatis-Plus / Spring Security / JJWT API。

不要复制整个旧 UserServiceImpl：其用户管理和旧 users/authority 类型缓存依赖超出新项目边界。抽取必要的只读身份权限查询即可。

文档没有现成的班牌设备注册、登录、心跳、固件或内容下发协议，也没有已实现的自动课表开关门；若期望这些能力，需要另行定义业务范围。

## 6. 后台任务和切换条件

待迁移的执行链包括 OA 每日同步、考试状态刷新、Quartz 启动恢复/定期对账、命令超期转 unknown、实际门锁定时 Job。

旧服务的 ExamStatusRefreshJob、LockScheduleReconcileService、LockCommandReceiptService 含独立 @Scheduled。spring.quartz.auto-startup=false 只停止 Quartz，不会停止它们。

切换必须：
- 关闭旧服务对应业务写入口、OA 同步、考试刷新、任务对账、回执超期及门锁执行，保留所需认证与其他业务。
- 新服务成为唯一发布和设备执行方；网关改路由不能代替旧任务停用。
- 重启只恢复未来任务，misfire 不补发历史门锁动作。
- submitted/unknown 幂等阻断、回执关联、人工 review、acknowledged 扣次一次性落实到业务。
- 当前 RAM Quartz 不提供集群协调。多实例前确定单执行方或集群方案，并保留数据库幂等保护。
- 完整作息和来源覆盖未核实前，未知状态不能被解释为空闲，不能启用自动开关门。

## 7. 上线验收与建议顺序

建议顺序：基础兼容修正 → 身份与共享库接入 → 教室/课表/考试/占用 → 门锁与任务 → 联调 → 停旧执行链并切换。

上线前至少验收：
1. 60 路由及 2 个固定拒绝入口；参数绑定、字段、状态码和时间格式。
2. 原服务真实登录/退出/权限变更；学院范围、管理员与 LOCK_ONLY 边界。
3. OA 失败保留旧课表；并发写入、事务回滚、行版本和规则变更后的覆盖可信度。
4. 真实设备发现/动作/回执、超时未知、重复请求、迟到回执、人工核查、停机释放。
5. 定时任务启停、次数、重启、misfire 和唯一执行方。
6. 网关 /api 前缀只加一次、原认证路由保留、CORS、LAN 通信与进程部署。
7. CI 中 SDK 依赖可获得；生产环境变量、日志、健康检查和回滚切换可操作。

SDK 当前依赖本地 install-file。持续构建可沿用 scripts/build.ps1，或上传到受控 Maven 仓库；干净环境不能假设开发机的本地 Maven 缓存已存在。
